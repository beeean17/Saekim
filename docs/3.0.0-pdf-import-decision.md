# Saekim 3.0.0 PDF Import Decision

## Decision

Saekim 3.0.0 ships without PDF-to-Markdown import.

The Tauri command boundary is reserved as `import_pdf(path)`, but the command intentionally returns an unsupported error in 3.0.0. PDF export remains available through the system print dialog.

## Rationale

The 3.0.0 migration goal is to replace the PyQt/QWebEngine runtime with a smaller Tauri shell. Keeping PDF import in this release would require either:

- bundling the existing Python/PyMuPDF/pdfplumber conversion stack as a sidecar, which weakens the size and startup-time wins, or
- rewriting the converter in Rust or another native pipeline, which is too much scope for the first Tauri release.

Deferring the feature keeps the MVP focused on file editing, preview, session restore, folder browsing, search, theme settings, and print-based PDF export.

## User-Facing Scope

Included in 3.0.0:

- Markdown and text file open/save/save-as.
- Folder tree browsing with lazy child loading.
- Markdown preview with code, Mermaid, and KaTeX rendering.
- PDF export through the OS print dialog.

Deferred from 3.0.0:

- PDF-to-Markdown import.
- automatic PDF file creation without the print dialog.
- Python sidecar packaging for document conversion.

## Future Boundary

The future implementation should keep the frontend contract stable:

```text
import_pdf(path) -> { path, name, content }
```

Implementation options for a later release:

- optional Python sidecar with explicit package-size measurement,
- Rust/native text extraction pipeline,
- plugin-style converter installed separately from the core app.

## Acceptance

- `import_pdf` exists as a Tauri command and returns a clear unsupported message.
- The frontend backend adapter exposes `importPdf(path)` for future UI wiring.
- Release notes state that PDF import is deferred in 3.0.0.
- `corepack pnpm build` and `cargo check` pass.
