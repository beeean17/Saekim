Saekim is a local-first desktop editor for Markdown and text-based documents.
It is built with Tauri 2, React, TypeScript, and Rust, and focuses on a split
editing workflow with a live preview, native file handling, and document assets
that stay next to the source file.

---

## Features

- Markdown editor with edit, preview, and split-view modes
- Live preview for Markdown with tables, images, blockquotes, task lists, code
  blocks, Mermaid diagrams, and KaTeX formulas
- Shiki syntax highlighting for fenced code blocks with an explicit language
- Scroll synchronization between the editor and preview
- Native file/folder open, save, save as, drag and drop, and OS file association
  handling through Tauri
- Markdown/text default-app support for macOS and Windows packaging
- PDF export from the rendered preview
- Local `.assets/` image workflow:
  - insert images by original path
  - copy images into a document-local `.assets/` folder
  - paste clipboard screenshots into `.assets/`
  - show `.assets` files in the workspace tree
- HTML file preview with browser-like and safer rendering modes
- Structured previews for JSON, YAML, TOML, CSV, TSV, and OpenAPI documents
- Preview block layout metadata for image/table/list/code/Mermaid/KaTeX blocks,
  including width, alignment, and 2-column/3-column grouping
- SQLite-backed metadata/session storage in the OS application support path

## Supported Files

Saekim can open known text file types directly and can also fall back to plain
text mode when an unknown extension is valid UTF-8 text.

| File type | Editing | Preview |
| --- | --- | --- |
| `.md`, `.markdown`, `.mdown`, `.mkd` | Markdown | Rendered Markdown |
| `.txt`, `.log`, `.env` | Plain text | Plain text |
| `.html`, `.htm` | HTML | Browser-like iframe or sanitized view |
| `.json` | JSON | Tree/API/raw preview |
| `.yml`, `.yaml` | YAML | Tree/API/raw preview |
| `.toml` | TOML | Tree/raw preview |
| `.csv`, `.tsv` | Delimited text | Table/raw preview |

## Requirements

- Node.js with Corepack enabled
- pnpm 9.15.4, managed through `corepack`
- Rust stable toolchain
- Tauri 2 system prerequisites for your OS

For macOS and Windows desktop bundles, use Tauri's platform setup guidance for
the required compiler/toolchain and native dependencies.

## Development

Install dependencies:

```bash
corepack enable
corepack pnpm install
```

Run the Tauri app in development mode:

```bash
corepack pnpm tauri:dev
```

Equivalent npm entrypoint:

```bash
npm run tauri dev
```

Build the frontend:

```bash
corepack pnpm build
```

Build desktop bundles:

```bash
corepack pnpm tauri:build
```

macOS app-only and DMG bundle shortcuts:

```bash
corepack pnpm tauri:build:app
corepack pnpm tauri:build:dmg
```

## Release Distribution

Saekim is distributed through GitHub Releases with separate artifacts for macOS
and Windows.

Recommended release flow:

1. Update `package.json`, `src-tauri/tauri.conf.json`, and `CHANGELOG.md` for
   the release version.
2. Build and verify the app on each target OS.
3. Create a Git tag such as `v3.0.1`.
4. Upload the generated desktop bundles to the GitHub Release.

macOS artifacts are built on macOS:

```bash
corepack pnpm tauri:build:app
corepack pnpm tauri:build:dmg
```

Windows artifacts should be built on Windows:

```bash
corepack pnpm tauri:build
```

Typical release artifacts:

| OS | Artifact |
| --- | --- |
| macOS | `.app` bundle and `.dmg` installer |
| Windows | `.msi` and/or `.exe` installer generated by Tauri |

For public macOS distribution outside a development machine, code signing and
notarization should be handled before uploading the release artifact.

## Project Structure

```text
.
├── src/                  # React frontend and retained legacy Python source
├── src-tauri/            # Tauri/Rust desktop backend
├── Licenses/             # Project license and third-party notices
├── _bmad-output/         # Planning and implementation artifacts
├── private/              # Private planning/archive submodule
├── package.json
├── pnpm-lock.yaml
└── vite.config.ts
```

The active 3.x application path is the React/Tauri code. Legacy PyQt/Python
files remain in `src/` for historical reference and migration context.
